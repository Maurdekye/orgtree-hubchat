# Choosing a recovery words file

On desktop or Android, open **I already use Hubchat > Recovery words** and
choose **Choose recovery words file**. This also works from the lost-key
screen's Recovery words option. Android opens its system file picker.
Select the `hubchat-recovery-<id>.txt` file Hubchat saved. Its 24 words fill
the input; check them, then press **Continue**. Typing and pasting still work.

The file stays on your device. Hubchat reads it locally, keeps no imported
filename or file copy, and sends only the words to the existing local
recovery command after Continue. The words leave the form when you go Back
or recover successfully. Keep the original backup safe: anyone who has
these words can use your identity.

Hubchat accepts its numbered export (including Windows line endings or a
UTF-8 BOM), or a plain text file containing 24 words separated by whitespace.
Files must be at most 64 KiB. A malformed, unreadable or oversized file gets
an error; Continue applies the same checksum and identity validation as typed
words. The export's address and saved date are metadata; the words determine
the recovered identity. Selecting a file never recovers automatically.

There is one shared recovery form for desktop, Android and the development
browser mock. The browser mock has no production account service. No new
native command, storage permission, hub request or agent tool is introduced;
file selection is available through the existing client UI/computer-use
workflow and recovery continues through `hc_restore_words`.

## Focused verification

`tools/proof-recovery-file.mjs` mounts the actual Onboarding component for
both layouts with synthetic APIs only. Its fixture is generated by
`recovery_file_fixture`, using the exact `recovery::to_file` formatter called
by the native Save recovery command. It checks import, ordinary typing and
Continue, malformed and unreadable files, size bounds, cancellation, late
reads versus edits/new selections/Back/unmount, and both layouts' visible
chooser geometry. The offscreen captures use Session 0, denied/stubbed
clipboard, blocked network and CDP to owned windows.

The mounted proof does not exercise a physical Android picker, Windows file
dialog or installed app. Wry 0.57.0's Android `onShowFileChooser` routes this
ordinary file input to `showFilePicker`/`createIntent`; no camera capture is
requested. Native focused recovery tests cover the export format and real
BIP-39/key/id round trips; the mounted API is synthetic.
